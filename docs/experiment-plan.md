# 实验计划

## 范围与状态

主论文为 SIGMOD 2025；VLDB 2023 作为 baseline。当前只有项目骨架和固定的上游代码版本，没有运行结果。

下列内容是待实施方案。必须在取得 SIGMOD 全文后核对实验图号、数据版本、baseline 配置、计时范围和汇总方式，再形成正式实验清单。不要将计划当作论文已经使用的全部设置。

## 执行阶段

1. **核对论文。** 建立“论文图表 → 数据集 → 方法 → 参数 → 指标 → 复现脚本”的映射；将论文数值和自己的测量分别保存。
2. **环境与构建。** 在 Linux 上记录硬件、系统、编译器、编译选项、OpenMP 配置和代码 commit；完成小数据试跑。
3. **数据准备。** 下载论文采用的具体数据版本，保留原始文件与校验值；转换为作者工具需要的超边格式。统计节点数、超边数和超边大小分布，并保存节点 ID 映射。
4. **正确性。** 先用可人工检查的小超图，再用真实小数据，逐节点比较 core number。注意强诱导子超图语义；普通投影图的 k-core 不能直接作为等价实现。
5. **主实验。** 对比 HyperCD* 与确认后的 VLDB Local-core 优化版本，统一数据和单线程条件。计时需区分加载、初始化、核心执行和端到端耗时；内存记录峰值 RSS。
6. **扩展实验。** 按论文设置安排 HyperCD 优化组合消融、数据规模扩展与线程扩展。所有抽样、节点排序及随机种子须记录。
7. **分析与报告。** 将原文数值、复现实测与同机相对性能放在一起，解释差异。明确哪些实验未覆盖、哪些因超时或内存限制未完成。

## 首轮建议

- 从上游附带的 coauth-MAG-History-full.hyp 开始验证流程；正式数据集名单待全文核实。
- 核心数据集覆盖不同规模和结构；初步目标 4–6 个论文采用的真实数据集。
- 建议每个配置重复 5 次，保存每次数据；最终汇总统计与论文保持一致，并补充波动信息。
- 并行实验从 1、2、4、8 个线程逐步扩展，实际线程上限按实验机器与负载确定。
- 十亿级实验在估算磁盘、峰值内存及运行时间之后决定，不作为尚未验证的必达目标。

## 结果记录字段

dataset、dataset_checksum、num_vertices、num_hyperedges、algorithm、commit、threads、seed、repeat、load_seconds、init_seconds、kernel_seconds、wall_seconds、peak_rss_kib、exit_code、status、log_path。

未测量的字段留空并说明原因；禁止以 0 代替未知值。超时与内存不足使用明确状态，不能作为普通成功运行计入平均值。

## 完成标准

- 选定配置可由文档和脚本重新执行，输入数据及作者代码版本可追溯。
- 在对齐节点映射后，算法输出通过正确性校验。
- 选定核心实验具备原始日志、结构化结果及可重新生成的图表。
- 报告逐项比较论文结果和复现结果，并说明范围、环境差异与限制。
